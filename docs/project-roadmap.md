# 项目路线图

| 能力 | 可验证的首期交付 | 依赖 |
| --- | --- | --- |
| 内容体系 | 分类、标签、三种 JSON Schema、中文指南与双语入口 | 原始证据 |
| 研究采集 | 七天和三十天窗口、来源状态、去重和可复核的评分 | 来源注册表 |
| 编辑流程 | 六个 Codex Skills、研究记录、安全审核 | 内容体系 |
| 自动化 | 周月报告、质量和链接检查、可选草稿 PR | 采集与编辑流程 |
| 发布 | MIT 与 CC BY 4.0、公开仓库、可追溯的验证结果 | 所有质量门禁 |

首期使用 Markdown 和 YAML，Python 命令从仓库根目录运行。来源观测、选题和指南元数据分别校验。报告同时输出便于审阅的 Markdown 和可重用的 JSON。

## 验收

1. 每份指南能从分类和人群索引找到，引用能直接定位。
2. 没有商业密钥时，公开来源仍可运行。部分源失败会留下状态，全部公开源失败会返回错误。
3. 社交指标保留平台和单位。评分中未知证据归零，单一社交平台候选默认观察。
4. GitHub Actions 的默认流程生成报告。可选 AI 只允许经单独质量检查的草稿进入 PR。
5. 发布前运行单元测试、内部和外部链接检查、配置校验和密钥检查。

主题配额供规划使用。Life 35%、Learning 30%、AI Skills 25%、Digital Skills 5%、Work & Growth 5%。首批以来源可核验且能立即练习的选题为先。

## 下一阶段

持续核对失效链接与复查日期。优先补齐小红书的人工需求样本，以及抖音获批账号的接口验收。根据三到五周积累的来源数据校准评分后，再调整选题权重。
