# 怎样写一份让同事知道下一步的工作汇报？

把实际进度、影响和待决事项写成一页，读者读完能决定下一步。

## 适用人群

需要向主管、同事或跨团队伙伴同步项目进度的读者。

读者标签　职场人士、管理者、自由职业者。

## 前置条件与不适用情况

知道汇报时段、受众和对方需要做的决定。需保密的细节留在访问受控的附件。正式合规报告采用组织模板。

## 准备、耗时与费用

准备前次计划、验收记录和待决定事项。约 20 分钟，免费。

## 操作步骤与验收

1. 先写一句状态，再写读者需要决定或协助的事项。 **验收**　开头两句包含状态和所需动作。
2. 每条进展写出结果、验收依据及影响。虚构例子「导出模板已在测试环境通过两条验收场景，周四可交给运营试用」。 **验收**　每条进展可定位到交付物、记录或日期。
3. 列出尚未解决的风险、下一步责任人与期限。 **验收**　每项待办能回答谁、何时、要交付什么。
4. 请同事只读首段和小标题，复述他们该做的事。 **验收**　复述与原意一致，再发送。

## 常见错误与排查

汇报只列会议或投入时，把每条改成已产生的结果，再附可以核对的证据。

## 风险与限制

高层简报与事故复盘的细节粒度不同。此结构适用于例行进度同步，必要时附详细记录。

## 最简行动清单

状态 → 决定 → 验收依据 → 风险与负责人 → 复述检查。
